Checkpoint Comparison

Five policy checkpoints evaluated across 10 trials per task. Select a checkpoint to see its per-task success rates and a sample rollout video.

What changed between checkpoints

pi05_base — Pretrained foundation model, no Baxter fine-tuning. Achieves 70% on T0 (red→far) showing strong transfer priors. Blue/green failure reveals colour-grounding limitation.
vel_99k — First fine-tune. Velocity-control action representation: policy predicts joint velocity commands directly. 4 tasks (no green). 100k steps. 0% success — gripper never closes; policy approaches but cannot grasp.
pos_200k — Switched to position control (predict target joint angles → P-controller converts to velocities). Added green block. 6 tasks. 200k steps. 20% overall; T2 blue→far gets 8/10 but mostly by pushing, not picking.
pos_v2 — Fixed demo recording: native 10 Hz (no downsampling). Added end-effector XYZ to state (8-dim → 11-dim). 500k steps. Final loss 0.004. 40% overall; block-lift rate doubles to 50%.
pos_v3 — Warm-started from pos_v2 (not from scratch). Lower peak LR (5e-5 vs 2e-4). 250 near-side demos per task (vs 100). 200k additional steps. Best result: 43% overall, 60% far-side average.

LoRA Fine-tuning

LoRA rank 16 on PaliGemma-2B + Gemma-300M action expert. Flow matching loss. AdamW, cosine LR, ~200–500k steps from pi05_base.

train.py pi05_baxter_pickplace_pos_v3
→
🤖

P-Controller Inference

Policy outputs target joint angles. P-controller: vel = clip(40 × (q_target − q), −1.5, 1.5 rad/s). WebSocket server + MuJoCo client at 10 Hz.

run_inference.py

π0.5 — Vision-Language-Action

π0.5 is built on PaliGemma (2B VLM) with an added 300M action expert communicating via cross-attention at every transformer layer. It generates actions via flow matching — denoising Gaussian noise into a 10-step action chunk.

xt = t · ε + (1 − t) · a
ut = ε − a
ℒ = MSE(vθ(xt, t, obs), ut)

VLM Stack

Two VLM components sit on top of the low-level policy: a task planner that decomposes a goal scene into an ordered task list, and a task monitor that verifies step completion in real time.

🗺️

VLM Task Planner

Gemma-3-12B-IT

Receives the current scene image and a goal scene image. Identifies which blocks need to move and in which order, producing a JSON task list that is passed to the low-level pick-and-place policy one task at a time.

Inputcurrent + goal images
Outputordered JSON task list
Queriedonce per scene
👁️

VLM Task Monitor

Gemma-3-12B-IT + GroundingDINO

Two-stage pipeline running live during each task execution. GroundingDINO detects named objects; Gemma verifies whether the current step goal is met by comparing current and reference frames.

CameraRealSense D435
